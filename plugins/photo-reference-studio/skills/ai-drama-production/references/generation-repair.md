# 생성과 수정 운영

Higgsfield·Seedance 작업에는 [서비스별 제작 지침](higgsfield-seedance-workflow.md)을 함께 읽는다. 연기·대화 결함은 [연기 수정](acting-dialogue.md), 동선·카메라 결함은 [블로킹](blocking-motion.md)으로 연결한다.

## 현재 기능 확인

연결된 도구의 모델·버전, 입력 방식, 참조 슬롯·역할, 시작/끝 프레임, 오디오 입출력, 길이·비율·해상도, 시드, 편집·연장, 가격과 작업 조회 기능을 확인한다. 확인일과 공식 문서/실제 스키마를 남긴다. 지원하지 않는 인자를 프롬프트로 대체해 제어 가능하다고 설명하지 않는다.

사용자 도구 선택을 존중한다. 대안은 현재 결함을 해결할 기능, 자산 재사용성, 비용과 편집 호환성으로 비교한다. 인기 순위만으로 바꾸지 않는다.

## 컷과 시도 기록

컷 ID·버전, 이야기 기능, 편집 사용 구간, 인물/공간 참조, 시작·끝 상태, 행동·시선, 카메라·조명, 대사·소리, 글자 후처리, 위험과 성공 조건, 결과 파일·작업 ID·청구 비용을 연결한다. 생성 길이와 사용할 길이를 구별하고 앞뒤 여유는 비용과 필요에 맞춘다.

이미지 기반 영상은 외형을 반복하기보다 변화·움직임을 명확히 쓴다. 텍스트 기반이면 외형·공간도 제공한다. 네거티브 입력은 지원할 때만 쓴다. 모델별 긍정문 권장 방식과 범용 프롬프트를 혼용하지 않는다.

출발 구조: `카메라 → 시작 상태 → 주 행동·속도·방향 → 상대/공간 반응 → 끝 상태 → 유지 조건`. 복수 행동은 순서·실현 시간을 검토한다. 모든 컷에 팬·줌·돌리를 동시에 요구하지 않는다.

비용은 `사용액 + 미완료 예약액 + 다음 시도 상한`으로 검사한다. 불명확한 실패는 조회 후 재시도하며 네트워크 오류를 무료로 취급하지 않는다. 원본 출력은 덮어쓰지 않는다. 예: `EP01_SC02_SH005_T03_raw.mp4`. 입력 버전·모델·설정·바뀐 변수·결과·비용을 기록한다. 시드가 있어도 모델 변경 뒤 동일 결과는 보장하지 않는다.

## 결함별 수정

| 결함 | 확인할 원인 | 수정 후보 |
|---|---|---|
| 얼굴·의상 변형 | 참조 상충, 가림, 누적 변형 | 원본 재연결, 사용 구간 단축, 키프레임 수정 |
| 시선·공간 불일치 | 축·카메라·배경 미정 | 공간도와 콘티부터 수정 |
| 손·물체 융합 | 접촉 불명확, 복잡한 이동 | 접촉 전후 분할, 삽입 컷, 부분 합성 |
| 평평한 연기 | 의도·상대 반응 없음 | 대본·행동 수정, 연기 참조, 반응 컷 |
| 입 모양·화자 오류 | 화자 혼합, 시간 불일치 | 오디오 확인, 화자 분리, 립싱크 시험 |
| 색·노출 불일치 | 색공간·빛·자동보정 | 색관리와 컷 매칭; 좋은 연기 보존 |
| 지루함 | 인과 없음, 반복 구도·길이 | 컷 선택·삭제·반응 위치 수정 |

수정 순서는 결함에 맞춘다. 재생성보다 편집·합성으로 고치는 편이 나으면 먼저 한다. 실험당 주요 변수 하나를 바꾸되 공간도 자체가 잘못됐다면 설계를 먼저 고친다.

승인 예산 안에서 재시도 기준을 정한다. 같은 실패가 반복되면 대사·행동 분할, 오프스크린 사건, 실사·합성 혼합 등 연출을 바꾼다. 무제한 재생성이나 모든 도구에 동일한 실패 횟수 규칙을 적용하지 않는다.
