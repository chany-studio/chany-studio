# Higgsfield·Seedance 장면 제작

Higgsfield 또는 Seedance로 서사 장면을 만들 때 읽는다. 공식 튜토리얼에서 확인한 제작 방법을 실행 기준으로 재구성한 자료다. 모델의 보장된 사양은 아니다. 근거와 확인 한계는 [출처 기록](higgsfield-source-ledger.md)을 따른다.

## 1. 생성 전에 결정할 것

대본에서 장면의 시작 상태, 문제, 인물의 선택, 끝 상태를 찾는다. 컷 목록은 그 변화를 관객에게 보여 주기 위한 것이다. 먼저 무슨 일이 일어나야 하는지 정하고 그다음 카메라를 고른다. 세 인물의 이야기를 교차 편집할 때도 각각의 인과가 독립적으로 성립해야 한다. 연속 숏드라마의 회차·반응·제작 단위는 [숏드라마 제작 지침](short-drama-workflow.md)을 함께 읽는다.

현재 서비스 화면이나 도구 스키마로 모델, 입력 종류, 길이, 화면비, 음성, 해상도, 참조 슬롯, 연장·음성 변경 기능과 비용을 확인한다. 튜토리얼의 480p 초안→1080p 재생성은 비용 절약 사례다. 사용자가 720p 무제한을 선택했다면 그 조건이 우선이다. 웹 구독 혜택을 API·플러그인·다른 길이에도 적용된다고 추정하지 않는다.

## 2. 재사용 자산을 만든다

프로젝트 안에서 인물·의상·소품·공간·장면을 구분하되 기존 폴더 구조가 있으면 유지한다. 자산 ID는 대본·제작표·Higgsfield에서 같은 이름과 버전을 쓴다. `@이름` 입력만으로 연결됐다고 판단하지 말고 실제 참조 칩·슬롯이 붙었는지 확인한다.

| 자산 | 준비 및 검사 | 참조의 역할 |
|---|---|---|
| 인물 | 확정 얼굴, 필요한 전신·측면; 머리·발·의상 누락 확인 | 정체성·체형 |
| 의상 | 정면·후면·신발·로고 위치; 기존 캐스팅에 적용 | 옷만 바꾸며 얼굴 보존 |
| 소품 | 같은 물건의 필요한 각도, 사용 전후 상태 | 형태·라벨·접촉 위치 |
| 공간 | 인물이 없는 마스터, 반대 각도, 문·창·책상·광원 | 구조·재질·빛 |
| 목소리/연기 | 사용할 권한이 있는 음성 또는 승인된 프리셋, 짧은 발화 시험 | 말투·음색·얼굴 움직임 |

캐릭터 시트의 큰 얼굴 한 장과 목 아래 전신은 중복 얼굴을 줄이는 선택지다. 이미 승인된 시트가 있다면 이 배치를 맞추려고 다시 캐스팅하지 않는다. 질감이 부자연스러우면 얼굴을 보존한 채 피부·머리·옷감 등 문제가 있는 부분만 수정한다. 질감용 사진이 인물의 정체성이나 배경 구도를 바꾸지 않도록 역할을 적는다.

반복되는 글자·로고는 정본 이미지 또는 편집 그래픽으로 관리한다. 참조에 정확한 글자가 있어도 영상의 모든 프레임이 정확하다는 뜻은 아니다. 같은 프롬프트를 계속 돌리는 것과 트래킹 합성 중 비용·품질이 나은 방법을 고른다.

## 3. 외형과 목소리를 연결하는 두 경로

**반복 출연자의 일관성이 우선일 때:** 영상 Element와 음성 참조가 실제 지원되는지 확인한다. 승인 얼굴과 사용 가능한 음성으로 짧은 발화·표정 변화를 만들고 얼굴, 목소리, 발음, 싱크를 검사한 뒤 재사용한다. 그림 시트만 넣었는데 목소리까지 고정됐다고 쓰지 않는다.

**연기는 좋고 음색만 맞지 않을 때:** 좋은 연기 테이크를 유지하고 Voice Change 등 지원 기능을 검토한다. 음성 변경 뒤 타이밍·억양·호흡·한국어 발음·싱크를 다시 확인한다. 튜토리얼의 ‘저렴하다’는 말로 비용 승인을 대신하지 않는다.

두 경로는 병행 가능하다. 영상 Element를 만들기 전에도 대본·블로킹 시험은 진행할 수 있다. 모든 장면에 음성 복제나 새 녹음을 의무화하지 않는다. 특정 실존인의 목소리를 모사할 권한은 별도로 확인한다.

## 4. 참조 역할과 우선순위를 명시한다

각 입력에 `ID / 가져올 속성 / 제외할 속성 / 적용 구간 / 충돌 시 우선순위`를 쓴다.

- 인물 시트: 얼굴·체형. 배경이나 포즈는 해당 장면의 지시를 따른다.
- 전용 의상·신발 참조: 해당 의상의 재단·색·로고. 얼굴을 바꾸지 않는다.
- 공간 이미지: 구조·재질·빛. 시작 프레임으로 쓸지 단순 공간 참조인지 구별한다.
- 블로킹 스케치: 인물 위치·방향. 완성 화면의 카메라나 외형으로 복제하지 않는다.
- 동작 영상: 지정한 몸동작만. 원본 인물·의상·배경·카메라는 제외할 수 있다.
- 프리비즈 영상: 합의한 카메라·컷·위치·타이밍. 회색 모형과 재질은 가져오지 않는다.
- 화면 콘텐츠 영상: 휴대전화나 모니터 안에서만 재생한다. 전체 장면을 대체하지 않는다.

같은 슬롯에 서로 다른 인물을 지정하거나 이름만 있고 파일이 빠진 참조를 제거한다. 외부 예시에도 슬롯 중복·빈 이름이 있을 수 있으므로 복사 전에 점검한다.

## 5. 생성 단위와 프롬프트

한 생성 블록은 이야기의 한 변화를 담는다. 여러 컷을 포함할 수 있지만 대사·행동·침묵이 들어갈 시간이 있어야 한다. 긴 블록이 무제한 범위를 벗어나면 자연스러운 대사 끝이나 행동 연결점에서 분할한다. 허용 길이에 맞추려고 한국어를 과속 낭독시키지 않는다.

[프롬프트 양식](../assets/seedance-scene-template.md)을 필요 항목만 채운다. 기본 정리 순서는 참조→사건→공간→행동과 대사→카메라→연기→빛·소리→유지 조건이다. 이는 누락을 줄이는 작성 양식이며 모델이 반드시 따르는 우선순위가 아니다. 영어 설명을 쓰더라도 한국어 원대사는 그대로 보존한다. 모델이 이해할 짧고 구체적인 문장이 우선이며 특정 언어가 항상 더 우수하다고 단정하지 않는다.

타이밍은 사건과 연결한다. 예를 들어 ‘상대 대사가 끝난 뒤 문을 닫는다’, ‘회의실이 바뀌었다는 말을 듣고 이동 방향을 바꾼다’처럼 원인을 적는다. 초 단위 표는 발화·반응 시간이 맞는지 검토한 다음 추가한다. 정확한 순서가 필요한 곳과 연기 호흡을 열어둘 곳을 구분한다.

## 6. 생성·선택·수정·연결

대표 장면의 성공 조건부터 정한다. 얼굴·공간이 맞아도 대사가 읽기처럼 들리면 연기 검수는 통과시키지 않는다. [연기 지침](acting-dialogue.md)으로 수정한다.

결과마다 쓸 수 있는 소스 구간을 기록한다. 한 테이크의 첫 대사와 다른 테이크의 반응을 연결할 때 같은 시선·손·소품·빛인지 확인한다. 다음 블록에 직전 대사나 동작을 조금 겹쳐 생성할 수 있으나 최종 편집에서는 중복 발화를 제거한다. 움직임 속 이음새도 실제 재생으로 확인한다.

좋은 동작 영상에서 다른 카메라를 얻거나 Forward Extend를 쓰는 방법은 지원 여부·비용을 확인한 뒤 선택한다. 연장에는 직전 끝 상태, 다음 동작, 유지할 얼굴·손·소품·조명을 함께 넘긴다. 이어붙였다는 이유만으로 연속성 합격 처리하지 않는다.

해상도를 높여 새로 생성한 결과는 새 테이크다. 낮은 해상도에서 확인한 연기와 동작이 유지됐는지 재검수한다. 업스케일과 재생성을 구별한다.

## 7. 사이트의 무제한 작업 운영

제출 직전 모델·길이·720p 등 사용자 조건, 음성·참조, 버튼의 무제한 표시를 확인한다. 새로고침이나 설정 변경 뒤에는 무료/유료 표시가 바뀔 수 있다. 무제한 표시가 사라진 상태로 제출하지 않는다.

접수한 작업 ID, 상태, 마지막 확인 시각을 남긴다. 동시 실행 제한이 나오면 기존 작업을 조회하고, 새 작업이 실제 등록됐는지 구별한다. ‘프롬프트 준비’, ‘접수’, ‘대기’, ‘완료’, ‘다운로드’, ‘재생 검수’는 서로 다른 상태다. 대기 시간이 길다는 이유로 유료 모드로 전환하거나 중복 제출하지 않는다.

A/B 비교는 가능한 설정·자산·대사를 동일하게 두고 주요 변수 하나를 바꾼다. 시드를 고정하지 못했거나 여러 값이 달라졌다면 통제 실험이 아닌 테이크 비교로 보고한다. 사용성 판단은 가능하지만 특정 문구가 개선을 일으켰다는 인과 주장은 하지 않는다.
