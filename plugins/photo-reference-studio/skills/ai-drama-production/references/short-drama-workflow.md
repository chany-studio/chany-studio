# 연속 숏드라마의 집필·생성·편집

Higgsfield 공식 숏드라마 영상·글·첨부 집필/프롬프트 스킬에서 확인한 방법을 제작 절차로 바꾼 자료다. [출처 기록](higgsfield-source-ledger.md)의 V3·W6를 참고한다. 조회수·수익·모델 성능에 관한 제작자의 주장은 작품의 성공 보증으로 사용하지 않는다.

## 1. 타깃이 알아보는 사건을 고른다

먼저 대상 관객, 인물의 당면 과제, 실제 사례의 출처와 창작한 부분을 구분한다. 업무 코미디에서는 ‘해외 진출이 어렵다’ 대신 언제 무엇을 해야 하는데 무엇이 막는지 화면으로 보이는 사건을 정한다. 해당 업종의 자료·인터뷰·원본 레퍼런스 확인 없이 ‘사장님이면 다 공감한다’고 단정하지 않는다.

후보마다 다음 질문에 답한다. 점수를 쓰면 기획자의 가설임을 표시한다. 조회수 예측이나 시청자 검증 결과로 부르지 않는다.

| 판단 항목 | 확인 질문 |
|---|---|
| 이해 | 첫 화면과 짧은 대화만으로 현재 하는 일을 알 수 있는가? |
| 타깃 공감 | 선택한 관객이 겪을 만한 시간·재고·돈·협업의 제약인가? 근거는 무엇인가? |
| 인과 | 그 제약 때문에 인물이 선택하고, 선택의 결과가 다음 말을 바꾸는가? |
| 반응의 차이 | 같은 사건을 두 사람이 다르게 받아들이는 이유가 있는가? |
| 웃음·감정 | 인물의 그럴듯한 시도가 예상 밖 결과를 만드는가? 대사 밖 반응으로도 읽히는가? |
| 시리즈 | 같은 인물의 관계에서 서로 다른 사건이 최소 10개 나오는가? 같은 상담을 반복하고 있지 않은가? |
| 제작 가능성 | 승인 자산과 현재 모델 조건으로 핵심 장면을 시험할 수 있는가? |

공식 예시의 신데렐라·신분 반전·패션쇼 플롯은 모든 프로젝트의 필수 장르가 아니다. 익숙한 상황에서 기대를 만들고 선택의 결과로 뒤집는 방법을 가져온다. 주인공을 무능하게 만들거나 상대역이 매번 정답을 가르치는 구조는 고친다.

## 2. 회차의 인과와 시리즈의 변화를 설계한다

한 회차에 `당장 보이는 문제 → 인물의 대처 → 새로운 정보/실패 → 선택과 결과`를 적는다. 첫 장면에 결말의 일부를 미리 보여 주는 방식은 선택지다. 사건 순서를 숨겨야 이해가 더 어려워지면 순서대로 시작한다.

에피소드 안의 작은 문제는 웃음이나 행동으로 정리할 수 있다. 후속 화로 이어지는 질문은 필요할 때 남긴다. 매번 문제를 해결하지 않은 채 끊거나 혜택 설명 직전에 유료 회차처럼 중단하지 않는다. ‘20~30초마다 감정 변화’는 공식 예시의 리듬 제안이며 한국어 대화의 의무 시간표가 아니다.

10화 이상을 요청받으면 회차표에 `상황 / 인물의 목적 / 장애 / 시도 / 반전 / 결과 / 관계 변화 / 확인된 브랜드 연결 / 사실 출처·창작 표시`를 둔다. 우선 5화 제작 요청이라면 1~5화 상세본과 6~10화 확장 개요의 완료 수준을 구별한다. 이름만 다른 같은 갈등을 늘려 편수를 채우지 않는다.

브랜드를 빼면 왜 이 사건의 해결 경로가 달라지는지 점검한다. 정보가 결정에 필요한 순간에만 등장시킨다. 브랜드가 제공하지 않는 서비스·비용 부담·성과를 실제 혜택처럼 창작하지 않는다. 사업 사실과 극 중 인물의 희망을 분리한다.

## 3. 대본을 연기와 화면으로 나눈다

대본에는 장면 표제, 보이는 행동, 화자와 정확한 대사, 상대가 새 정보를 받는 순간을 쓴다. 콘티에는 화자의 말뿐 아니라 그 말을 듣는 사람의 얼굴이 언제 보이는지 기록한다. [연기 지침](acting-dialogue.md)을 함께 적용한다.

같은 말에도 인물마다 기대가 다르면 반응이 달라진다. 반응을 ‘놀란다’로 끝내지 말고 무엇이 예상과 달라졌는지 적는다. 감정 변화가 핵심인데 뒤통수만 보이면 반응 컷이나 보이는 두 사람 구도로 바꾼다. 의미 없는 입장·착석 동안 대사를 멈추지 않는다. 필요한 경우 걷거나 자료를 보는 동안 대화를 시작하되 말과 동작의 우선순위를 정한다.

등장 인물의 얼굴을 나중에 공개할 때는 먼저 기대를 만드는 정보가 있어야 한다. 앞·뒤 구도 반복이나 긴 침묵 자체를 긴장감으로 간주하지 않는다. 정지 화면으로 이 리듬의 성공을 판정하지 않는다.

## 4. 자산과 상태를 관리한다

기존 승인 얼굴·의상·공간부터 재사용한다. 묶은 머리, 안경 착용, 젖은 옷 등 상태가 달라지면 기존 인물을 기준으로 상태별 버전을 만든다. 새 얼굴을 생성해 대체하지 않는다. 주연·조연·엑스트라·휴대전화 속 사진의 역할을 별도로 적어 사진 속 인물이 장면 속 인물로 바뀌는 오류를 막는다.

반복 공간은 문·책상·통로·광원을 알 수 있는 마스터가 유용하다. 한 번만 나오는 공간까지 모두 새 기준 이미지로 만들 필요는 없다. 기존 공간을 분위기 참고로만 쓰면 구조까지 복제하지 않도록 `재질·조명만 참고 / 장소 구조는 새 장면 설명`을 구분한다.

음성 프로필에는 인물 ID, 언어·방언, 음역·질감, 기본 속도, 존댓말 관계, 승인 음성/검증된 테이크를 연결한다. 독립 생성마다 필요한 동일 프로필을 전달하고 장면별 의도와 강약만 조정한다. 그림 시트와 목소리가 자동으로 고정된다는 첨부의 주장은 검증되지 않았다. 실제 지원하는 음성 참조와 모든 연결 컷의 청취 대조를 우선한다.

## 5. 회차·장면·컷·생성 블록을 구분한다

하나의 회차에는 여러 장면이, 하나의 장면에는 여러 컷이 들어갈 수 있다. 생성 블록은 서비스가 허용하는 길이·입력에 맞춘 작업 단위다. 한 번 생성한 영상을 한 회차로 취급하지 않는다. 공식 첨부의 ‘최대 30초’도 현재 사용자의 사이트·모델·무제한 조건을 확인하기 전에는 적용하지 않는다.

| 제어 방식 | 적합한 경우 | 확인할 것 |
|---|---|---|
| 연속 한 컷 | 시선과 티키타카를 끊지 않고 시험할 때 | 불필요한 자동 컷, 두 사람 반응의 가시성 |
| 순서만 정한 다중 컷 | 구도 순서는 필요하지만 정확한 초는 중요하지 않을 때 | 대사와 컷의 인과, 축·소품 연속성 |
| 시간표가 있는 다중 컷 | 특정 말·행동·음악에 맞출 때 | 발화 시간, 컷 실행 오차, 잘린 반응 |
| 자유로운 보조 화면 | 정보 전달용 제품·환경 소재를 얻을 때 | 필수 행동·라벨·실제 제품 상태 |

프롬프트는 각 블록만 읽어도 인물·공간·시작 상태·대사·끝 상태를 알 수 있어야 한다. ‘앞 장면처럼’, 누락된 자산 이름, 등장하지 않는 인물 태그를 제거한다. 관리용 회차 번호는 파일명과 기록에 두고 생성 지시와 분리할 수 있다. [장면 양식](../assets/seedance-scene-template.md)을 사용한다.

생성 순서는 편집 순서와 다를 수 있다. 가장 어려운 대화부터 시험하고 합격한 조건으로 대화의 앞뒤와 삽입 컷을 만든다. 휴대전화 화면·제품 라벨·손 같은 정보 컷이 필요하면 독립 작업으로 계획한다. 삽입 컷으로 맥락 없는 대사나 잘못된 인과를 가리지는 않는다.

## 6. 좋은 부분을 보존하며 고친다

첫 결과를 대본·자산과 대조한다. 무엇이 좋고 어느 타임코드가 틀렸는지 구체적으로 기록한다. 예를 들어 얼굴·동선·카메라는 맞고 억양이 바뀌었으면 유지할 요소와 바꿀 음성 요소를 분리한다. 좋은 연기를 버리고 장면 전체를 새로 만들지 않아도 되는지 먼저 검토한다.

편집에서 장면의 끝을 말의 끝에 기계적으로 맞추지 않는다. 상대가 이해하는 반응과 다음 행동의 시작이 포함돼야 하는지 확인한다. 연결한 최종본을 처음부터 끝까지 정상 속도로 보고 듣는다. 일부 프레임·자막·자동 분석만 확인했다면 그 범위와 남은 검사를 적는다.

## 제작 인계물

요청 범위에 맞춰 시리즈 바이블·회차표·시놉시스·시나리오/대본·연기표·컷별 콘티·자산표·생성 프롬프트·생성 및 편집 순서·테이크 선택표·최종 검수표를 연결한다. 동일 내용을 각각 새 문서로 반복할 필요는 없다. 각 문서의 대사·자산 ID·버전은 같아야 한다.

현재까지의 근거는 문서와 사례 검토다. 이 방법으로 만든 영상의 연기·공감·재미는 별도로 검증한다.
