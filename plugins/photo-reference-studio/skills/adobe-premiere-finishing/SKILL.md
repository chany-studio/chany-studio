# Premiere editing and finishing

Follow the shared [beginner experience contract](../chany-studio/references/beginner-experience.md) and [native production integration](../chany-studio/references/native-production-integration.md). Reuse the approved brief and asset versions. Explain visible outcomes in plain language; keep technical setup internal unless requested. These skills add production guidance, not an Adobe connection or permission to spend.

Keep the editorial timeline authoritative. Read the current script/cut, selected sources, delivery requirements, and existing project. Save a new project/sequence revision; preserve the accepted master. Identify the active sequence, exact frame rate, picture/audio versions, and which application owns subtitles before editing. A research update does not authorize changing a locked cut.

## Editorial setup

For trims, shot timing, AE turnover and XML proof, read [editing-and-handoff.md](references/editing-and-handoff.md). For relinking, proxies, variable frame rate, performance or source interpretation, read [media-and-conform.md](references/media-and-conform.md). Templates organize work; they do not determine the job's rate, color or audio layout.

Build voice/story timing first, place evidence where it answers the narration, and leave actual reading/reaction holds. Keep dialogue, music, and sound effects separate. Preserve original source audio where an accepted lip-synced performance requires it.

## Montage and continuity

For a sequence of related actions, time compression, match cuts, or sound bridges, read [montage-and-sound-continuity.md](references/montage-and-sound-continuity.md). Keep source evidence, focal continuity, and the final voice intact while testing the sequence rhythm.

For a long-form fine cut, a reference-quality review, or changes after a short representative cut, read [editorial-passes-and-export-sync.md](references/editorial-passes-and-export-sync.md). It keeps story and polish decisions distinct and documents evidence-based encoded-audio alignment checks.

## AE and reusable graphics

Choose Dynamic Link, MOGRT, or rendered shots by editability, change frequency and playback cost. Keep original shots and transition handles. Follow the AE transfer section of [editing-and-handoff.md](references/editing-and-handoff.md); for title templates and caption ownership read [captions-and-graphics.md](references/captions-and-graphics.md).

## Sound and color

For channel mapping, dialogue repair, submixes, music, automation, loudness and stems, read [dialogue-and-mix.md](references/dialogue-and-mix.md). Judge actual encoded output after routing, not source WAV meters alone.

For source interpretation, SDR/HDR choices, shot matching and AE round-trips, read [color-and-roundtrip.md](references/color-and-roundtrip.md). Match the technical transforms before designing a look. Protect authoritative graphics from unintended global grading.

## Automation

Read [automation.md](references/automation.md) for API/version constraints. Use the available supported API or native UI; do not call imaginary Premiere tools through an unrelated Adobe connector. XML is an interchange file, not a saved native `.prproj` or a guarantee that effects/styles survived.

## Finishing

Read [finishing-and-delivery.md](references/finishing-and-delivery.md) for output variants, representative export tests, full-program QC, packaging and recovery. Read [captions-and-graphics.md](references/captions-and-graphics.md) when importing, styling or exporting captions. Keep captioned/clean outputs and stems aligned; verify the package from its collected location.

Use only the relevant sections for the job. Record a method as documented, locally tested, or production accepted according to actual evidence. Report native-app operations separately from handoff preparation. Never claim full automation or visual quality from installation, documentation or XML parsing alone.
