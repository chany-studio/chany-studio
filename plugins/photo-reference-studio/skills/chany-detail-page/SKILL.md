# Chany Detail Page

Build only the requested image modules for a product-detail page and keep them coherent as one evidence-based sales narrative.

Read [references/detail-page-system.md](references/detail-page-system.md) for module selection, prompts, family locks, and QA.

## Workflow

1. Record the sales objective, product source, approved fact ledger, exact copy, target storefront, width or ratio, and accepted campaign lock.
2. Propose a compact module plan when the user has not named modules. Confirm the effective asset count before multiple paid generations.
3. Give every module one purpose and one primary claim: hero, clean product, feature or benefit, source-visible detail, lifestyle, factual comparison, or closing CTA.
4. Maintain product scale, palette, lighting, typography plan, spacing, and copy hierarchy across the family while varying composition only as each module requires.
5. Inspect every module individually and then the family. Do not average away a failed member.

Never invent specifications, efficacy, certification, comparison advantages, prices, or legal claims. A product-page hero belongs here when it is part of the page narrative; a standalone media placement belongs to `chany-ad-creative`.

Inspect the connected tool schema before use. If exact typesetting or generation is unavailable, return the module plan, clean visual plates or prompts that can be produced, and a precise list of pending work.
