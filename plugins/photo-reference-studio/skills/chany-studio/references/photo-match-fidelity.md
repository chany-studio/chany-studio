# Two-image photo matching and label fidelity

Read for every product-photo reference selection. This strengthens photo-reference-execution.md; it does not permit extra spending or a hidden change of technique.

## Photo-only quick start

When Chany is invoked with only a clearly recognizable product photograph and no conflicting task, inspect it and offer a **free Behance photo-reference board as the reversible starting direction**, without making the beginner provide a marketing brief. Say that proposed direction in one sentence and proceed with included free discovery; do not generate until a selection authorizes the presented production plan. Respect an already stated video/edit/research intent. If the photo's role or subject is unclear, ask only that missing fact. Do not promise that installing a skill forces the host to invoke it for every image-only message; verify implicit discovery separately in a new Work chat.

## Plan before generating

Use the original product image and the exact chosen reference as two actual image inputs. Inspect each at its available resolution. For a reference match, inherit the reference's aspect ratio unless the user specifies another; disclose any crop/ratio conflict. Record these internally, using observed approximations rather than invented camera settings:

- product count, camera elevation/view, orientation/tilt and visible faces;
- product center x/y and visible bounding-box height/width as fractions of the frame; background boundaries, top/side negative space and cropped edges;
- key-light direction, hard/soft shadow, shadow direction/length, highlight placement, background tonality, reflection and contact;
- product silhouette/parts, label boundaries/colors, logo and every legible label line, including units and punctuation. Mark unreadable text unknown; never reconstruct it from brand knowledge or replace it with marketing copy.

The reference controls **placement, camera and light**. The product controls **geometry, materials and label content**. Preserve the real product's proportions instead of stretching it to the other brand's width. Do not preserve source pose/light when they conflict with the reference. If a requested view needs an unseen surface, state that specific limit; a single photo cannot establish unknown packaging details. Do not invent lens focal length, Kelvin, aperture, exposure or physical light power from a reference photo; match its observable lighting appearance.

Generate through the allowed live image tool, using both actual files/images and a prompt compiled from these observations. Ask for the highest appropriate supported quality/resolution for the approved output, without making up API options. Use the native host image tool when that is the user's requested workflow; record its model as undisclosed if the tool does not identify it. Do not silently claim it is GPT Image 2.6. Connected paid generation retains its live model/quote/approval contract.

Prompt structure:

> Image 1 is the actual product and the sole authority for its geometry, parts, materials, logo and label. Image 2 is the selected reference and the authority for framing, camera view, placement, lighting, shadows, surface and background. Make Image 1's product occupy the measured composition of Image 2: [observed anchors]. Preserve the product proportions. Match [observed light/shadow/reflection]. Remove the reference brand and substitute the real product. Preserve each legible label line exactly: [verified text and line breaks]; do not paraphrase, translate, add, omit or redesign typography. Keep the source label's arrangement and proportions. Do not retain Image 1's old pose/background/lighting when inconsistent with Image 2. Add no new copy.

This is a generation target, not a guarantee of exact pixels or text.

## Inspect and correct, within the agreed limit

Before presenting a completed image, open the full-resolution output. Compare it with **both** originals. Inspect the label large enough to read; OCR can flag a discrepancy but is not proof by itself. Inspect the pump, bottle width/height, logo, all readable lines and quantity/unit text. Compare position, crop, camera angle, scale, highlight and shadow against the recorded reference anchors. Record `pass`, `fail`, or `unverified` per property; do not average away a failed label or composition requirement. Text that was unreadable in the source cannot be marked exact.

If the first image has a label defect and a correction is authorized, perform one targeted **AI edit**, carrying the failed draft as the edit base plus the original product and selected reference as actual inputs. Keep accepted composition/light fixed; identify only the wrong label region and supply the source-verified lines. Do not launch another unconstrained reshoot or omit the reference. If the tool supports a real mask, use its documented mechanism; otherwise state that localized preservation is requested but not guaranteed. Reinspect the entire output after correction for new drift.

Honor `AI generation only`: do not silently use code compositing, paste a replacement label, retype it onto the image or use a deterministic layer operation. Do not re-propose a method the user already declined. The default bound remains one initial generation plus one defect-specific correction under existing consent and any applicable cost ceiling. If it still fails or text cannot be verified, preserve the draft and report the exact unmet requirement. No success claim based merely on two input images, an attractive render or the tool returning success.
