# Automatic Behance photo references

For a supplied product photo plus a reference request, start included free **Behance** discovery immediately. Do not ask the user which site to use, whether to search Behance, or for a marketing interview first. When Chany is invoked with a recognizable product photo alone and no conflicting task, use the same reversible starting direction. Explicit source, count, edit-only or video instructions take precedence. An unselected host may not invoke Chany for every image-only message; never promise universal automatic activation from installation alone.

## Search and verify

1. Inspect the product locally. Search its category, not the user's uploaded photo or private brand details. Use the relevant L1 and at most one direct L2 from the shared industry taxonomy. Behance is the provider; the taxonomy's legacy Pinterest domain is not this lane's domain.
2. Prefer an available included image-search tool with `behance.net` filtering. If that supported filter yields no usable results, the same category plus `Behance` is one bounded index fallback. Retain only results pairing a public `https://www.behance.net/gallery/<numeric-id>/...` project with an actual image returned for that project. Other domains are not candidates, even when a mixed index or widget returns them.
3. If the current host exposes a browser, its public Behance search and project UI can be used to inspect the actual image. Do not assume the current Work conversation has the developer's Chrome connection. No hidden endpoints, copied cookies, access-control bypasses or paid scraping. A 403 ends that retrieval route; do not keep retrying it. An independently supported public preview or browser route may be checked once within the same bound, but do not claim it works until observed.
4. Accept project-associated public image assets on `mir-s3-cdn-cf.behance.net` or `mir-s3-cdn-cf.behance.com` only when their exact URLs are returned by the source/search result. Do not synthesize URLs. Do not reuse the Pinterest-only preview server or change its allowlist. Use an actually available native image-result display, supported inline preview or browser; do not download to evade presentation restrictions.
5. Separate discovery, user-visible display, model-visible inspection and generation-input availability. An asynchronous widget that gives no result/source list is not proof of a source-filtered board or of inspected pixels. A text description alone cannot support a final visual recommendation. Show six actual distinct images by default; honor an explicit count, with zero skipping research. Report requested/visible/missing counts when incomplete.

Use at most six discovery calls total, including any alternate transport or widget search. Stop a transport after two calls with no usable new candidates or an access block. Preview no more than three times the requested count of distinct candidates; never retry the same blocked asset blindly. Do not silently switch to Pinterest, Unsplash, Pexels, retailers or another source. A blocked route is an access limitation, not permission for a new paid service.

## Number, select and produce

For each visibly inspected finalist retain stable number, project URL, creator when shown, exact selected image URL/media ID, category query, product fit and observed composition/light. Different images within one project need separate image identifiers; a project URL alone cannot resolve a selection. Rank for product compatibility, observable camera/framing/lighting, creative diversity and production feasibility. Never infer sales or actual client commissions from views, likes, brand names or polished concept work.

Ask for the reference choice only after displaying the usable board. For research + production, combine that choice with the concrete production scope under [reference recovery](reference-recovery.md). Use [two-image fidelity](photo-match-fidelity.md): the actual product photo and exact selected reference image must both reach the generator. The product controls identity and readable label facts; the reference controls framing, placement and observable light. Preserve AI-only requests, verify the generated image against both inputs, and disclose any failed label or composition checks. A public portfolio is not a blanket commercial reuse license.
