# Purpose-led intake and decision reuse

Use this shared intake before choosing a concept, production owner or model. It applies through the beginner contract even when a specialist is invoked directly. It is not a new interview stage or a requirement to initialize a project.

## Read first, ask only what changes the result

Inspect the current request, attachments and any approved brief/state. Current explicit instructions override project defaults; conflicting authority facts require clarification, not guessing. Keep supplied facts, visible observations, proposed creative assumptions and unknowns distinct. Never infer an audience's sensitive traits from a photo.

Resolve only the fields relevant to the requested output:

| Decision | What it changes |
| --- | --- |
| Intended effect and next action | purchase, inquiry/booking, understanding, awareness, save/share, or a bounded asset edit; not every output needs a sales CTA |
| Viewer and decision context | what that viewer needs to understand, see or trust; customer facts need sources, not invented personas |
| Channel, placement and deliverable | framing, readable copy, sequence, ratio, duration and count; distinguish carousel units from card count |
| Product/service truth and constraints | authoritative product, approved offer/proof/copy, required disclosures, rights and must-preserve properties |
| Reference roles | product/identity authority versus style/composition or observed motion; a style reference does not override product truth |
| Delivery priorities | final versus draft, deadline and any supplied budget/quality/speed preference; a budget is a ceiling, not permission to spend it |

When intent is genuinely ambiguous (a product photo plus "알아서 만들어줘"), ask the highest-impact question first: "이 콘텐츠를 본 사람이 무엇을 하길 바라세요?" Offer grounded choices such as 구매하기 / 문의·예약하기 / 제품을 기억하기, with a recommendation only when the context supports one. Do not quietly choose a purchase campaign merely because a product exists. "인스타에 올려요" establishes a channel, not necessarily a conversion goal.

Use one to three short questions in one round, only for unresolved choices that would materially change the output. Do not pack a long questionnaire into one question. Audience or placement can be a second/third question when needed. Do not add separate preference cards on top. Skip the interview entirely when the needed answers are known. A follow-up is only for a genuine safety, authority or feasibility blocker; unknown non-blocking details stay pending or are disclosed as proposed defaults in the existing confirmation. Claims, rights, spending and uploads are never default-approved.

Offer everyday outcomes, not model names, lens lengths, lighting terminology or codec settings. "알아서 추천해 주세요" lets the assistant propose direction; it is not paid execution consent. In Claude use `AskUserQuestion` when exposed; in ChatGPT/Codex use an available native question mechanism, otherwise equivalent numbered prose. Never claim a UI exists when unavailable. Project setup keeps its mandatory pre-write approval from the project contract.

## Proportional paths

- **Known single output:** "내 제품 + 이 사진 느낌 + 인스타 구매 광고 1장" → use those facts; no new purpose interview or automatic replacement reference search.
- **Editorial/educational content:** optimize understanding, reading and saving; do not force a discount or buy button. Required price, date or benefit facts remain pending until supplied.
- **Bounded edit/cutout/assembly:** "이 사진 배경만 지워줘", "영상 끝 2초 잘라줘" → the change itself supplies the job. Ask only about an ambiguous target or preserve boundary; no campaign interview, reference board or new key visual.
- **Reference-led video:** reuse the observed reference packet and selected remake/edit path. A public Reel link alone is not an editable source or upload permission. A missing source may block editing but not an honest planning handoff.
- **Multi-output campaign:** capture a shared purpose once and a short purpose/placement delta per output; do not send the user through each specialist's interview. Separate non-ad editorial assets from conversion placements.

## Carry decisions into production

Keep the resolved intent alongside the existing brief or asset specification, not in a second competing brief. For each material decision, retain its source locator, status (`supplied`, `observed`, `proposed`, `approved`, `unknown`) and affected asset scope. This status describes provenance or adoption, never legal clearance. An inferred audience is `proposed`; approving a concept does not verify a product claim.

Derive a short production direction: intended effect → one message → what must be visible → reference treatment → operation and output constraints → QA criteria. Then apply [latest-model-routing.md](latest-model-routing.md). A model is selected for the job; it does not determine the customer's goal.

Present the purpose, recommended direction and relevant trade-off inside the existing confirmation card, not as another approval gate. Compile the technical prompt internally unless requested. Reuse the accepted source, direction, exact copy and governing still at handoffs. Read the current brief/state again before resuming; ask again only about a changed or unresolved decision. If a change affects quoted inputs, model, scope or options, renew only the affected paid approval. Do not automatically migrate or rewrite existing project instructions; durable setup-policy changes use `chany-project update`.

Project setup records intent and labelled defaults in `brief.md`; current operation, recommendation and unresolved decisions live in `state.md`. One-off work keeps the same compact facts in its existing asset/job record. No project folder or extra standalone skill is required.
