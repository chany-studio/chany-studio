# 최신 AI 이미지·영상 소식 기반 플러그인 점검

> 이 문서는 구현 전 점검 기록입니다. 사용자의 후속 구현 요청에 따른 변경·자료 선별·검증·사이트 반영 결과는 [2.18 종합 보고](RELEASE-2.18-REVIEW.md)에서 확인합니다.

확인일: 2026-11-17 (한국 시간). 대상: Chany’s Studio 2.17.0, `main`, 기준 커밋 `7734ac7`과 현재 작업 트리. 스킬 45개(기존 호환용 진입점 포함)의 모델·도구 관련 문구를 검색하고 공통 모델 정책, 비용·복구, 영상 편집, 드라마 통합, 초보자 흐름을 상세 대조했다. 모든 스킬의 실제 제작 품질을 검증한 것은 아니다.

시작 전부터 수정되어 있던 `ai-drama-production/SKILL.md`, `chany-studio/SKILL.md`, `chany-studio/references/routing.md`는 보존했다. 이번 작업은 조사·점검이며 배포용 스킬, 버전, 설치본, 공식 사이트는 변경하지 않았다. 프로젝트 설정은 `ready`; 소스 구현 요청이 아니므로 구현·변경 후 품질 스킬 체인은 실행하지 않고 현 상태의 회귀 검사만 실행했다.

## 판단 기준: 사용자가 이 플러그인을 쓰는 이유

핵심은 원하는 결과를 일상어로 요청하면, 실제 제품·브랜드 자료를 기준으로 기획·연출·제작·수정·검수를 이어 주는 것이다. 모델 선택은 이 작업을 돕는 수단이다. 제품과 라벨의 보존, 레퍼런스 구도 반영, 여러 콘텐츠의 일관성, 기존 승인 자료 재사용, 불필요한 생성과 재결제 방지에 집중해야 한다. 스킬 수나 최신 모델 이름만 늘리는 것은 차별화가 아니다.

## 우선순위별 점검 결과

### 1. 이미지 기본값 정책 재검토 — 우선

`skills/chany-studio/references/image-generation-runtime.md`는 2026-09-15 사용자 정책에 따른 GPT Image 2.5 기본값을 명시한다. 현재 MCP에서도 `gpt_image_2_5`가 조회되므로 고장 난 모델을 참조하는 상태는 아니다. 다만 최신 권장 후보는 재검토해야 한다.

현재 MCP에서 2.6은 `gpt_image_2_6`(Sunburst)와 `gpt_image_2_6_flare`로 분리되어 있다. 2.5의 `variant` 인자를 이름만 바꿔 재사용해서는 안 된다. 기본값 변경 시 공통 계약뿐 아니라 연결 스킬·매니페스트·회귀 검사·가이드를 함께 갱신해야 한다. 2.5 관련 문자열은 플러그인 내 MD/MJS/JSON 검색 기준 67개 행에 남아 있다.

제안: 새 작업의 기본 모델 정책과 기존 프로젝트의 승인 모델을 분리하고, 실제 지원 기능을 확인한 뒤 신규 작업 기본값을 정한다. 이전 결과물은 새 모델이 나왔다는 이유만으로 재생성하지 않는다.

### 2. GIF·SVG 산출물 규칙 추가 — 우선

현재 공통 라우팅에는 SVG용 후보가 있지만 2.6의 네이티브 GIF/SVG 분기와 전용 검수 기준은 없다. `chany-ad-creative`, `chany-motion-design`, `image-asset-production`, 공통 모델 라우팅·검수 계약을 연결하는 편이 별도 모델 스킬을 만드는 것보다 적합하다.

MCP 확인: 2.6의 `output_format`에 GIF/SVG가 있고 SVG는 참조 이미지를 받지 않는다. 제품 사진을 SVG 요청에서 임의로 버려서는 안 된다. GIF는 반복 경계·재생 시간·프레임, SVG는 실제 벡터 구성·문자·렌더 결과를 확인해야 한다. OpenAI 직접 API에서 소개된 `complexity`는 이번 Higgsfield 스키마에 없으므로 그대로 전달하지 않는다.

### 3. 영상 모드별 제약 갱신 — 우선

`latest-model-routing.md`의 후보 표는 2026-09-19 스냅샷이며 Gemini는 1.1을 제시한다. 실시간 확인 원칙은 잘 갖춰져 있어 이 표가 곧 실행 오류라는 뜻은 아니지만, 추천이 오래된 후보에 치우칠 수 있다.

이번 MCP 확인:

- Gemini 1.2: 텍스트/단일 첫 프레임은 3~15초, 참조/첫·끝 프레임은 3~10초, 편집 원본은 3~15초. `duration`의 최대값만 보고 모든 모드를 15초로 취급하면 안 된다. 공식 Higgsfield 소개의 이미지 수와 MCP 설명도 다르므로 실행 직전 모드 계약을 우선한다.
- Seedance 2.5: 4K, 편집·전후 연장, `draft`/`draft_job_id`가 조회된다. 초안의 유효기간과 최종 렌더의 별도 과금을 작업 기록에 연결할 필요가 있다.
- Seedance 2.5 Flash: 480p/720p이고 참조 수 한도가 본 모델과 다르다. 동일 참조를 무조건 복사해 최종 렌더로 넘길 수 있다고 설명하면 안 된다.
- Kling 4.0 검색에서는 독립적인 동일 이름 모델이 확인되지 않았고 Genjutsu Lite 등 관련 결과만 나왔다. 검색 결과만으로 서비스 전체의 미지원이나 완전 지원을 단정하지 않는다.

### 4. Short Drama Studio 연결 — 조건부 추가

11월 16일 공식 발표는 데스크톱 early preview와 Claude MCP 이용을 안내한다. 현재 `ai-drama-production`에는 이야기·연기·연속성·컷 제작의 역할 분리가 있고, 참조 모드에서 첫 프레임을 강제하지 않는 규칙도 이미 있다. 이 구조는 유지할 가치가 있다.

이번 세션 도구 목록에는 `get_drama_ads_config`가 있지만 그것만으로 Short Drama Studio 전체 프로젝트 관리가 검증된 것은 아니다. 둘을 같은 기능이라고 단정하지 않는다. 추가 연결은 스크립트→회차→인물/공간/소품→장면/클립의 식별자와 기존 승인 자산을 이어 주는 범위로 설계한다. 대본 요청을 전체 시리즈 자동 생성으로 확대하지 않는다.

### 5. GPU 대여는 기존 생성 비용과 별도 처리 — 확장 시 필수

현재 도구 목록에는 GPU 대여·실행·상태·중지가 있다. 전용 GPU 수명·종료 규칙은 플러그인에서 검색되지 않았다. 이미지 한 장 비용과 달리 실행 중 시간제 과금이 이어지고, 중지하면 파일이 사라질 수 있다.

도입한다면 시간당 요금뿐 아니라 총 사용 한도·최대 실행 시간·중지 조건·결과 반출·세션 회수까지 기록해야 한다. 이미 있는 작업 영수증/중복 방지 원칙은 유지하되 GPU 전용 종료 절차를 보완한다. 이번에는 GPU 조회·대여·생성을 실행하지 않았다.

### 6. Adobe·Canva는 실행 가능성을 먼저 확인 — 보류/관찰

Adobe 스킬이 앱 설치, 도구 연결, 실제 실행, 렌더 검증을 구별하는 점은 적절하다. Firefly 발표를 Premiere/After Effects 네이티브 프로젝트 자동 제어의 증거로 쓰지 않는다. Canva의 생성 결과와 편집 가능한 디자인도 구별한다. 새 기능은 실제 연결을 검증한 후 기존 제작·인계 경로에 더한다.

## 유지할 핵심 설계

- 모델과 공급자를 실제 도구에서 확인하고 불명확하면 실행을 보류하는 규칙.
- 제품의 실제 형태·라벨 보존과 레퍼런스 구도 반영을 각각 검사하는 규칙.
- 승인된 브리프·이미지·대본·자산을 재사용하고 반복 질문을 줄이는 규칙.
- 생성 실패 시 기존 작업부터 회수하고 중복 결제를 피하는 규칙.
- 단순 수정에는 기획 전체를 반복하지 않고 해당 부분만 바꾸는 규칙.
- 기획 완료, 파일 생성, 재생 검수, 게시를 구분하는 규칙.
