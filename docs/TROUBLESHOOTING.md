# Chany's Studio 문제 해결

[공식 설치·사용설명서 (Notion)](https://jolly-phlox-79c.notion.site/Chany-s-Studio-3c783e9464668140b794ee076be24406)

## 저장소를 추가했지만 플러그인이 안 보임

주소가 정확한지 확인합니다.

```text
https://github.com/chany-studio/chany-studio
```

화면 표시명은 **Chany's Studio**지만 기존 업데이트 호환성을 위한 내부 식별자는 `photo-reference-studio`입니다. 마켓플레이스에서 이 식별자를 찾아 Refresh 또는 Update한 뒤 앱을 다시 시작하세요.

## 업데이트했는데 예전 기능이 나옴

다음 상태는 이전 설치본일 가능성이 높습니다.

- 버전이 `2.3.0`보다 낮음
- 대표 스킬 `chany-studio`가 없음
- 상세페이지·광고·UGC가 전문 스킬로 분리되어 있지 않음
- 11개 업종 스킬이 보이지 않음
- `chany-campaign-video`, `chany-video-assembly` 또는 `chany-preflight`가 보이지 않음
- 레퍼런스를 이미지 대신 링크나 HTML만 제공함
- Claude `/project-studio` 초기화가 질문 카드 없이 바로 파일을 쓰려고 함

Refresh 또는 Update 후 반드시 새 대화나 새 작업을 시작하세요. 이미 열린 대화는 시작할 때 읽은 이전 지침을 계속 사용할 수 있습니다.

## 기존 `auto-photo-production`만 보임

2.0에서는 `auto-photo-production`이 이전 요청과 문서를 위한 호환 안내로만 남습니다. 새 작업에서는 다음처럼 시작하세요.

```text
Claude Cowork(자연어 자동 선택): 이 제품의 광고 캠페인을 시작해줘.
ChatGPT Work: @chany-studio로 이 제품의 광고 캠페인을 시작해줘.
Codex: $chany-studio로 이 제품의 광고 캠페인을 시작해줘.
```

한 가지 결과라면 ChatGPT Work에서 `@chany-detail-page`, `@chany-ad-creative`, `@chany-campaign-video`, `@chany-ugc-ads`, `@chany-video-assembly`, `@chany-preflight`처럼 `@`로, Codex에서 같은 이름 앞에 `$`를 붙여 해당 전문 스킬을 직접 사용합니다. Claude Cowork에서는 원하는 결과를 자연어로 요청하면 해당 전문 스킬을 자동 선택합니다.

## `/project-studio` 또는 `chany-project`가 보이지 않음

- 설치 상세 버전이 `2.3.0`인지 확인하고 Refresh 또는 Update합니다.
- Claude Cowork에서 짧은 `/project-studio`가 보이지 않으면 `/photo-reference-studio:project-studio`를 사용합니다.
- ChatGPT Work는 `@chany-project`, Codex는 `$chany-project` 또는 “현재 폴더를 광고 프로젝트로 설정해줘”라고 요청합니다.
- ChatGPT에서 `/project-studio …`는 슬래시 메뉴에 등록되지 않습니다. 일반 메시지로 전송되면 호환 별칭으로 처리되며, 입력창에서 가로막히면 `@chany-project`를 사용합니다.
- 업데이트 후 새 대화나 새 작업을 시작합니다. `AGENTS.md`, `CLAUDE.md`와 런타임별 설정은 다음 세션에서 확실히 로드됩니다. `.codex/agents/*.toml`은 로컬 Codex 클라이언트용이며 ChatGPT Work는 `AGENTS.md`의 호스팅 위임 규칙을 사용합니다.

## Claude에서 Ask your question 카드가 나타나지 않음

- 설치 상세 버전이 `2.3.0`인지 확인하고 플러그인을 Update한 뒤 새 Cowork 작업을 시작합니다.
- `/project-studio <설명>` 또는 `/photo-reference-studio:project-studio <설명>`으로 **초기화**를 실행합니다. `status`와 `doctor`는 결정이 없으면 질문 카드를 강제로 열지 않습니다.
- 입력과 기존 파일에 정보가 충분하면 누락 정보 카드는 생략될 수 있지만, 정확한 설계안 뒤의 `승인 후 생성 (권장)`·`설계 수정`·`취소` 카드는 파일 쓰기 전에 표시되어야 합니다.
- 현재 호스트가 `AskUserQuestion`을 노출하지 않거나 빈 답·시간 초과·기술 오류를 반환하면 플러그인은 일반 텍스트 확인으로 전환합니다. 이 경우 카드를 표시했다고 주장하거나 빈 답을 승인으로 처리해서는 안 됩니다.
- 사용자가 `취소`를 선택하거나 명시적으로 중단하면 일반 질문으로 되돌리지 않고 Chany 단계를 끝내야 합니다.
- Chany 승인 전에 `AGENTS.md`, `CLAUDE.md` 또는 `.chany-studio/**`가 생겼다면 작업을 중단하고 `doctor`로 관리 구역과 백업 상태를 확인하세요. 단, 같은 요청에서 별도 승인한 Moai 단계가 먼저 만든 `.moai/**`는 정상일 수 있습니다.

## ChatGPT에서 `/project` 또는 `/project-studio`가 슬래시 명령으로 나오지 않음

ChatGPT Work는 이 두 이름을 네이티브 슬래시 메뉴 명령으로 등록하지 않습니다. `/project`는 Moai의 프로젝트 기능을 뜻하고, `/project-studio`는 Chany's Studio의 일반 메시지 호환 별칭입니다.

```text
Moai 프로젝트: 설치된 Moai의 project 스킬로 이 프로젝트를 설정해줘.
Chany 프로젝트: @chany-project로 이 광고·콘텐츠 프로젝트를 설정해줘.
```

입력창에서 `/project-studio` 전송이 막히면 `@chany-project`를 사용하세요. Codex에서는 `$chany-project`, Claude Cowork에서는 `/project-studio`를 사용합니다.

## Moai 조건부 체인이 동작하지 않거나 필수 모드가 중단됨

일반 `/project-studio`는 기존 Moai 기록을 자동으로 재사용합니다. 새 Moai `project` 단계는 현재 호스트가 정확한 스킬을 같은 요청 안에서 실제 호출하고 기다릴 수 있을 때만 승인안에 포함됩니다. 설치 흔적만 있거나 호출 기능이 없으면 Chany 단독으로 계속하고 수동 2단계를 안내하며, `/project`를 대신 실행하거나 비슷한 산출물을 만들어 성공으로 표시하지 않습니다. `--with-moai` 또는 `moai-chain`은 필수 모드라서 Moai나 해당 호출 기능이 없으면 Chany 쓰기 전에 중단합니다.

1. 설치 화면에서 Chany's Studio와 Moai의 설치·활성화 여부를 각각 확인합니다.
2. 설치 또는 업데이트 뒤 새 대화나 새 작업을 시작합니다.
3. 두 플러그인을 각각 한 번 확인한 뒤 일반 `/project-studio`를 다시 요청합니다.
4. Moai를 반드시 실행해야 하면 `--with-moai`, 건너뛰려면 `--chany-only`를 사용합니다.

## 프로젝트 설정 뒤 Moai 전문 체인이 호출되지 않음

`/project-studio`의 프로젝트 체인과 이후 광고 제작의 전문 체인은 별개입니다. 프로젝트가 설정된 뒤에도 Moai의 모든 스킬을 항상 실행하지 않으며, 현재 산출물·관할·주장·메시지·인플루언서·상세페이지·디자인·미디어 위험에 직접 필요한 스킬이 설치되어 있고 현재 세션에서 호출 가능할 때만 조건부로 연결합니다.

1. 새 대화나 새 작업에서 Chany's Studio와 해당 Moai 패키지가 모두 설치·활성화됐는지 확인합니다.
2. 필요한 Moai 스킬의 **정확한 설치 이름, 출처와 버전**을 확인합니다. 예전 문서의 이름을 비슷한 스킬로 바꿔 실행하면 안 됩니다.
3. 전문 인계에는 실행한 스킬 이름·출처·버전, 검토한 객체 버전, 사용한 공식 출처와 확인 날짜, 발견 사항과 미해결 질문이 있어야 합니다.
4. 스킬이 없으면 Chany 단독 흐름으로 브리프와 초안을 계속하되, 필요한 전문 검토를 실행했다고 표시하지 않습니다. 공식 근거나 전문가 판단이 필요한 항목은 `draft-only` 또는 `blocked`로 남깁니다.

Moai의 결과는 범위가 제한된 상위 근거입니다. 전체 캠페인의 게시 승인이나 법률적 승인을 대신하지 않으며, 정확한 최종 버전은 별도로 `chany-publication-review`를 거쳐야 합니다.

## 기존 `.moai` 파일과 Chany 설정이 충돌함

`.moai/**`는 Moai의 정본이며 Chany's Studio에는 읽기 전용입니다. Chany's Studio가 이 경로를 수정·삭제·이동·백업하려 하면 작업을 중단하고 변경 제안을 거부하세요. 기존 Moai의 제품·구조·기술 정보는 자동 재사용하되, 광고 캠페인별 결정은 `.chany-studio/brief.md`가 담당합니다.

두 파일의 정보가 다르면 어느 한쪽을 조용히 덮어쓰지 말고 현재 요청에 맞는 값을 사용자에게 확인해야 합니다. `.moai`를 변경해야 하는 문제는 Moai에서 해결한 뒤 새 세션에서 Chany 설정을 다시 읽습니다.

## `CLAUDE.md`의 Moai 하니스 구역이 바뀌려고 함

Chany's Studio는 다음 마커 사이의 Moai 하니스 구역을 내용과 순서까지 그대로 보존해야 합니다.

```text
<!-- moai:harness-start -->
…
<!-- moai:harness-end -->
```

Chany 연결에는 `@AGENTS.md`가 첫 번째 비어 있지 않은 줄에 필요할 수 있지만, Moai 구역을 다시 쓰거나 안으로 끼워 넣으면 안 됩니다. 마커가 중복·중첩됐거나 한쪽만 있으면 자동 수정을 승인하지 말고 Moai에서 하니스를 복구한 뒤 다시 시도하세요.

## 프로젝트 지침을 만들 수 없음

- 파일이 연결된 로컬 프로젝트 또는 쓰기 가능한 작업 폴더에서 실행했는지 확인합니다.
- 홈 폴더, 파일시스템 루트와 플러그인 캐시는 안전을 위해 초기화 대상이 아닙니다.
- 기존 `AGENTS.md`나 `CLAUDE.md`에 충돌이 있으면 Chany's Studio가 제시한 병합 내용을 먼저 승인합니다.
- 같은 위치의 `AGENTS.override.md`는 `AGENTS.md`보다 우선합니다. 발견되면 사용자 내용을 보존한 연결 블록을 추가할지 먼저 확인합니다.
- 설정 중에는 이미지·영상 생성, Higgsfield 호출, 자동 커밋과 푸시를 하지 않습니다.
- `doctor` 모드는 읽기 전용입니다. 발견된 문제를 고치려면 별도로 수정 승인을 합니다.

기존 파일을 수정했다면 이전 내용은 `.chany-studio/backups/`에서 확인할 수 있습니다. 이 폴더에는 비밀번호나 API 키를 넣지 마세요.

## Higgsfield 연결 요청이 반복됨

- 앱이 표시하는 연결 또는 로그인 버튼을 사용합니다.
- 인증을 마친 뒤 처음 작업하던 대화로 돌아옵니다.
- 브라우저와 데스크톱 앱의 로그인 계정이 동일한지 확인합니다.
- 관리형 워크스페이스에서는 Higgsfield 연결 허용 여부를 관리자에게 확인합니다.
- 비밀번호, API 키, 액세스 토큰이나 인증 코드를 채팅에 붙여 넣지 않습니다.

Higgsfield 사용 권한, 요금제와 생성 크레딧은 플러그인에 포함되지 않습니다.

## 정적 이미지에 GPT Image 2가 선택되지 않음

생성형 정적 이미지와 부분 편집의 요청 기본값은 `gpt-image-2`입니다. 실행 요약에서 `요청 기본값`과 `실제 해석 모델`을 확인하세요.

- 현재 도구가 모델 선택기를 제공하면 정확히 `gpt-image-2`를 선택해야 합니다.
- 선택기가 숨겨져 있으면 현재 도구 문서나 런타임 정보로 GPT Image 2가 확인될 때만 같은 이름을 표시할 수 있습니다.
- 모델을 확인할 수 없으면 `unavailable`로 멈춰야 하며, 공급자 기본값을 GPT Image 2라고 추정하면 안 됩니다.
- 다른 모델은 사용자의 명시적 지정, 승인된 프로젝트 정책 또는 검증된 필수 기능 부재가 있을 때만 해당 범위와 이유를 기록하고 승인받아 사용합니다.
- 모델이나 공급자를 바꾸면 기존 견적·유료 생성 승인·크리에이티브 승인은 해당 범위에서 다시 받아야 합니다.

영상·음성·UGC 영상과 로컬 클립 조립은 이 정적 이미지 기본 모델 정책에 포함되지 않습니다.

## Marketing Studio 템플릿이 자동 실행되지 않음

새 Marketing Studio의 템플릿 방식은 현재 Higgsfield 웹 전용입니다. Chany's Studio는 제품 입력, 브랜드 정보, 카피와 추천 템플릿을 준비한 뒤 웹에서 완료하도록 안내합니다. 웹 전용 기능을 Claude 안에서 완료했다고 표시하면 안 됩니다.

MCP에서 직접 실행 가능한 일반 이미지·영상·Soul·오디오 또는 지원되는 UGC 워크플로와 혼동하지 마세요.

## UGC 영상 생성이 시작되지 않음

- Higgsfield 연결이 현재 대화에서 활성화됐는지 확인합니다.
- 제품 이미지와 크리에이터 이미지의 역할을 각각 지정합니다.
- 목표 길이, 비율, 유형과 승인 CTA를 제공합니다.
- 여러 생성 단계가 있다면 크레딧 사용 범위 확인에 답합니다.
- 해당 템플릿이 웹 전용이면 ChatGPT Work의 `@chany-ugc-ads` 또는 Codex의 `$chany-ugc-ads`가 제공한 입력안을 Marketing Studio에서 실행합니다.

```text
제품 이미지는 제품 권위 입력, 인물 이미지는 성인 크리에이터 권위 입력이야.
15초 9:16 Product Review UGC로 만들고 CTA는 “지금 확인하기”로 고정해줘.
```

## 첨부한 제품 이미지가 영상 첫 프레임에 반영되지 않음

제품 장면은 승인된 스틸을 먼저 정하고, 현재 연결 도구의 스키마가 노출하는 **이미지 조건 모드**와 **첫 프레임 역할**에 연결해야 합니다. 일반 이미지 첨부 역할이 자동으로 첫 프레임이 된다고 가정하지 않습니다.

- 오류가 모드 또는 참조 역할을 지원하지 않는다고 명시하면 프롬프트를 먼저 고치지 말고 현재 모드·역할 조합을 확인합니다.
- 즉시 검증 오류였고 유료 작업이 만들어지지 않았다는 근거를 확인한 뒤에만 같은 스틸로 수정된 요청을 준비합니다.
- 모드·역할·워크플로 또는 유료 옵션이 달라지면 새 유료 생성 사전검토와 승인을 받습니다.
- 시간 초과·연결 끊김·청구 상태 불명은 모드 오류가 아닙니다. 기존 작업 또는 영수증을 찾기 전 같은 요청을 다시 보내지 않습니다.

## 영상 조립 또는 레퍼런스 프레임 추출이 실행되지 않음

먼저 ChatGPT Work의 `@chany-preflight` 또는 Codex의 `$chany-preflight`로 이번 단계에 필요한 도구만 프로젝트에 영구 변경 없이 점검합니다. Claude Cowork에서는 “이번 영상 조립 환경을 점검해줘”라고 요청할 수 있습니다.

```text
ffmpeg·ffprobe와 한글 폰트를 실제 버전·폰트 증거로 확인하고,
사용 가능·누락·관찰 불가·차단을 구분해줘. 설치는 시작하지 마.
```

플러그인은 특정 Claude, ChatGPT Work, Codex 또는 로컬 환경에 도구가 기본 설치돼 있다고 가정하지 않습니다. 환경 점검은 설치나 프로젝트 파일 변경 없이 시작하며, 글리프 렌더가 꼭 필요하면 운영체제 임시 공간만 사용하고 즉시 정리합니다. 설치나 업그레이드가 필요하면 현재 운영체제·실제 패키지 관리자·다운로드와 저장 위치를 먼저 보여주고 별도 승인을 받아야 합니다. 실행할 수 없는 경우에도 클립 manifest, 타임스탬프 계획과 빈 성과표는 만들 수 있습니다.

## 조립 뒤 두 번째 클립부터 소리가 사라짐

`@chany-video-assembly` 또는 `$chany-video-assembly`로 모든 입력의 오디오 스트림을 다시 측정합니다. 오디오가 없는 승인 클립에는 목표 출력과 같은 형식의 무음 트랙을 넣고, 서로 다른 코덱·프레임률·타임베이스를 정규화한 뒤 새 파일로 조립합니다. 최종 파일도 다시 측정해 실제 오디오 존재와 재생 경계를 확인해야 합니다. 원본 클립은 덮어쓰지 않습니다.

## 캠페인 영상 생성과 UGC 중 무엇을 써야 할지 모름

- 제품 광고, 브랜드 필름, 프로모션 모션처럼 콘셉트와 장면 연출이 중심이면 `@chany-campaign-video` 또는 `$chany-campaign-video`를 사용합니다.
- 리뷰, 언박싱, 튜토리얼, 실제 경험 형식처럼 크리에이터가 중심이면 `@chany-ugc-ads` 또는 `$chany-ugc-ads`를 사용합니다.
- 이미 승인된 영상을 조립하거나 한 구간만 교체하려면 `@chany-video-assembly` 또는 `$chany-video-assembly`를 사용합니다.

제품 형태나 라벨이 영상에서 무너지면 같은 생성 작업을 반복하지 말고, 승인된 GPT Image 2 기준 이미지 위의 줌·팬 방식이나 권한 있는 실제 영상이 더 정확한지 `chany-campaign-video`의 모션 판단을 다시 실행합니다.

## 컷 교체 뒤 프레임레이트나 오디오가 달라짐

원본 마스터와 교체 클립을 다시 측정하고 `replace-segment` 모드에서 정확한 시작·종료 시점과 오디오 정책을 지정합니다. 원본 마스터의 프레임레이트와 오디오가 기본 권위이며, 승인된 납품 사양이 다른 값을 요구할 때만 변경합니다. 결과는 원본을 덮어쓰지 않고 새 버전으로 만들며 컷의 진입·종료 프레임과 음향 연속성을 확인합니다.

## 레퍼런스 이미지가 대화에 표시되지 않음

Claude Cowork에서 플러그인 상세의 `reference-preview` 연결과 컴퓨터의 Node.js 18 이상을 확인합니다. 2.2.4부터 이 도구는 항상 로드되며, 스킬은 Pinterest 검색 전에 호출 가능한지 먼저 확인합니다. 업데이트 후에는 반드시 새 Cowork 작업을 시작하세요.

```text
링크나 HTML만 주지 말고 `reference-preview`를 사용해 Pinterest 후보 6장을 현재 대화 안의 실제 이미지로 다시 보여줘. 표시되지 않는 후보는 같은 검색 풀의 사용하지 않은 Pinterest 후보로 교체해줘.
```

연결은 공개 Pinterest 미리보기만 가져옵니다. 가져올 수 없는 후보는 사용하지 않은 Pinterest 후보로 교체해야 하며 링크나 HTML은 직접 이미지 표시를 대신하지 않습니다. 안전하게 표시할 후보가 6장보다 적으면 결과를 미완성으로 알리고 선택이나 유료 제작을 시작하지 않습니다.

## 레퍼런스 검색이 L3로 내려가거나 창작 수식어를 붙임

올바른 검색은 L1 광역 카테고리 한 번에서 시작하고 필요할 때 직접 L2 하위 카테고리 하나만 추가합니다. 세 번째 분류, 다시 쓴 세 번째 검색어 또는 지역·플랫폼·스타일·무드·색·카메라·렌즈·조명·비율·브랜드·연도 같은 수식어를 검색어에 붙이면 안 됩니다.

```text
잘못된 검색
Food Photography → Restaurant Photography → Brunch Cafe Photography
moody Seoul cafe 85mm cinematic Instagram ad

교정된 검색
L1: Food Photography
L2: Restaurant Photography
```

다음처럼 다시 요청하세요.

```text
검색을 중단하고 L1 광역 카테고리부터 다시 시작해줘.
필요하면 직접 L2 하나까지만 검색하고, 나머지 무드·색·렌즈·플랫폼 조건은 검색어가 아니라 Visual DNA와 제작 프롬프트에 넣어줘.
```

L2 결과가 약해도 L3로 내려가지 말고 L1 후보의 선별 기준을 개선합니다.

## 제품·라벨·모델·의류가 변형됨

해당 결과를 승인하지 말고 원본을 다시 권위 입력으로 지정합니다.

```text
ChatGPT Work: @chany-image-edit로 원본을 다시 권위 입력으로 사용해 관찰된 변형만 복원해줘.
Codex: $chany-image-edit로 원본을 다시 권위 입력으로 사용해 관찰된 변형만 복원해줘.
현재 캠페인 방향, 구도와 조명은 유지해줘.
```

투명 누끼는 생성형 재그리기보다 배경 제거를 우선합니다. 새 아트 디렉션은 여러 번 수정한 이미지가 아니라 깨끗한 원본에서 시작합니다.

## 광고 문구가 틀림

정확한 문구를 텍스트로 다시 제공하고 승인 카피로 고정합니다.

```text
승인 문구는 아래와 같아. 철자, 숫자와 줄 구분을 바꾸지 마.
메인: ...
기간: ...
CTA: ...
```

이미지 생성만으로 정확한 문구가 어려우면 텍스트 없는 비주얼 플레이트를 만들고 조판 가능한 도구로 카피를 적용해야 합니다.

## 부분 수정이 전체 이미지를 바꿈

```text
ChatGPT Work: @chany-image-edit로 배경 밝기만 수정해줘. 제품, 문구, 구도, 크기, 조명 방향과 그림자는 모두 고정해줘.
Codex: $chany-image-edit로 배경 밝기만 수정해줘. 제품, 문구, 구도, 크기, 조명 방향과 그림자는 모두 고정해줘.
```

한 번에 한 가지 속성만 요청하고 지원되는 경우 마스크 또는 명확한 영역을 제공합니다.

## 생성 비용이 예상보다 큼

MCP와 자동화 채널의 생성은 일반 크레딧을 사용할 수 있습니다. 전체 캠페인에서는 다음처럼 요청하세요.

```text
생성 전에 산출물별 예상 생성 횟수와 승인 지점을 보여주고, 승인 전에는 유료 생성을 시작하지 마.
```

## 유료 생성 응답이 끊겼거나 결제 여부가 불명확함

타임아웃, 연결 해제 또는 알 수 없는 결제 상태가 발생해도 같은 생성을 바로 다시 제출하지 마세요. 중복 작업과 이중 크레딧 사용이 생길 수 있습니다.

```text
재제출하지 말고 원래 요청의 영수증이나 작업 참조로 상태·작업 기록을 먼저 확인해줘.
기존 작업이 생성됐으면 그 작업을 이어받거나 결과만 가져오고, 생성되지 않았음이 확인될 때만 다음 단계를 제안해줘.
```

원래 작업의 상태를 확인할 수 없으면 새 요청으로 추측해 실행하지 말고 중단 상태와 확인이 필요한 항목을 알려야 합니다. 토큰, 인증 헤더, 임시 업로드 주소와 내부 비밀값은 문제 해결 기록에 붙여 넣지 마세요.

## 견적 뒤 요청을 바꿨는데 이전 승인이 사용됨

승인은 화면에 제시된 한 버전에만 유효합니다. 프롬프트 의미, 권위 입력이나 입력 역할, 모델·워크플로, 유료 옵션, 생성 수량, 길이, 비율, 언어, 배치 크레딧 한도가 달라지면 무료 견적이나 비용 미리보기를 다시 확인하고 새 승인을 받아야 합니다. 단순 표시 형식 변경만 비용·의미·입력에 영향을 주지 않는 경우는 예외입니다.

```text
변경된 요청을 새 버전으로 표시하고 현재 스키마로 다시 사전 점검해줘.
최종 프롬프트, 입력 역할, 실제 옵션, 서버 조정값과 제공자 크레딧 정보를 보여준 뒤 새 승인을 요청해줘.
```

서버가 선택한 기본값이나 조정값을 사용자가 원래 승인한 값처럼 표시해서는 안 됩니다.

## 게시 검수가 멈추거나 이전 검수 상태가 사라짐

`chany-publication-review`는 다음 네 상태만 사용합니다.

- `blocked`: 금지·기만·안전·권리 또는 중대한 근거 문제가 남아 게시할 수 없음
- `draft-only`: 초안 작업은 가능하지만 사실·근거·공식 출처·권리·공시·버전 또는 검토자가 미완료
- `ready-for-named-human-review`: 정확히 고정된 버전의 다섯 검토 레인이 끝나 이름이 지정된 권한 있는 사람의 결정을 기다림
- `reviewed-by-named-owner`: 이름이 지정된 권한 있는 사람이 그 정확한 버전에 대해 범위가 명시된 결정을 기록함

카피, 번역, 가격·오퍼·CTA, 공시, 크롭·배치·자막·렌더, 대상·관할·채널·목적지, 근거·권리 또는 의존한 플랫폼 규칙이 바뀌면 이전 검수는 새 버전에 승계되지 않습니다. 변경된 후보는 최대 `draft-only`에서 다시 시작하고 영향받은 레인과 최종 렌더를 재검토해야 합니다.

검수 시점의 현재 정부·규제기관·플랫폼 공식 1차 출처, 발행·갱신일 또는 `unknown`, 확인 날짜와 적용 범위를 기록하세요. 출처가 없거나 충돌하면 기억으로 채우지 말고 게시를 보류합니다. 마지막 결정에는 이름, 역할과 권한 범위가 확인된 사람 검토자가 필요합니다.

이 상태는 추적 가능한 마케팅 제작 검수이며 법률 자문, 법률적 승인, 규제 인증, 플랫폼 사전 승인이나 게시 권한을 약속하지 않습니다.
